# Texture Optimizer ユーザーガイド

**言語:** [EN](user-guide.md) · [한국어](user-guide.ko.md) · 日本語

> **Unity 2022.3.22f1 を使用する VRChat プロジェクト向けに作成されています。ほかの Unity バージョンではテストされておらず、互換性がない可能性があります。**

VRChat プロジェクトを想定しています。パッケージ自体は VRChat SDK に依存しません。

Texture Optimizer は、インポート済みテクスチャのサイズを確認し、解像度上限を意図的に引き下げるための Editor 専用ツールです。シーンやプレイヤービルドには何も追加しません。ウィンドウを開くだけでアセットのスキャン、変更の提案、最適化が自動実行されることはありません。

インストール方法、必要環境、バージョンを固定したパッケージ URL は [README](../README.ja.md#インストール--方法は一つだけ選択) を参照してください。一つの方法で、一つのコピーだけをインストールしてください。古い単体版の optimizer スクリプトはインストール前に削除してください。

## 始める前に

1. 作業を保存し、テクスチャの元ファイルと `.meta` ファイルを含めてプロジェクトをコミットまたはバックアップします。
2. バージョン管理システムでチェックアウトやロックを使用している場合は、先にテクスチャとその `.meta` ファイルを編集可能にします。
3. Play Mode 以外で作業します。インポーター変更の適用と復元には Edit Mode が必要です。
4. インポート後のテクスチャサイズを小さくするために、どこまで品質を下げられるかを考えます。最初はプロジェクト全体ではなく、重要度の低いテクスチャを数枚選んで試してください。

**共有テクスチャへの変更は、すべての参照元に影響します。** 一つのオブジェクトを選択しても、専用のテクスチャコピーが作成されるわけではありません。編集したテクスチャを使用するほかのシーン、プレハブ、マテリアルにも、新しいインポート上限が適用されます。

このワークフローでは、Unity Undo による復元は保証されません。optimizer のローカルバッチバックアップと、ご自身のバージョン管理履歴またはプロジェクトのバックアップを使用してください。

## 1. スキャン範囲を選ぶ

**Tools → prokjs → Texture Optimizer** を開き、**Scope** を選択します。

| Scope | 一覧に含まれるもの |
| --- | --- |
| **LoadedScenes** | 現在読み込み済みのシーン内のオブジェクトから取得できる対応参照と、シーンのスカイボックスマテリアル。ほかのシーンは開きません。 |
| **SelectedObjects** | 選択したシーンオブジェクトまたはプレハブアセットと、その子孫オブジェクト。スキャン前に少なくとも一つのオブジェクトを選択してください。 |
| **Folder** | `Assets` 内の指定フォルダーと、その配下にあるテクスチャアセット。 |
| **ProjectAssets** | `Assets` 配下のテクスチャアセット。`Packages` は意図的に除外します。 |

シーン／選択範囲の走査では、Renderer のマテリアル、Terrain のマテリアル／レイヤーのテクスチャ、Unity UI の Graphic のテクスチャ／マテリアル、ライトの Cookie を読み取ります。参照先マテリアルのテクスチャプロパティも調べます。**Include inactive objects** は、オブジェクトを対象とするスキャンに非アクティブなオブジェクトを含めるかどうかを指定します。

これは完全なビルド依存関係解析ではありません。アバターのアニメーションクリップ、任意のスクリプト、Addressables による読み込み、あらゆるカスタムコンポーネントだけから参照されるマテリアルやテクスチャを検出できるとは主張していません。フォルダー／プロジェクトのスキャンはアセットの一覧であり、使用中か未使用かを証明するものではありません。

**Edit cap for** を選択します。

- **Default:** デフォルトの最大テクスチャサイズを変更します。明示的なプラットフォームオーバーライドが優先されるため、Standalone や Android の出力は変わらない場合があります。
- **Standalone:** Standalone の上限を変更します。有効なオーバーライドがない場合、変更した上限を適用するときに、Default から継承した設定でオーバーライドを有効にする場合があります。プレビューの注意を確認してください。
- **Android:** Android に対して同じ上限／オーバーライドの処理を行います。Android 実機の測定や、Android の圧縮形式の自動選択は行いません。

**Scan / Refresh** をクリックします。現在の状態のスナップショットを読み取り、インポート設定は変更しません。スキャンをキャンセルすると一覧が部分的な状態で残ることがあり、その旨がレポートに表示されます。完全な一覧が必要な場合は再スキャンしてください。

Scope、対象、非アクティブなオブジェクトの設定を変更すると、既存のスナップショットは古い状態になります。次の適用プレビューを作成する前に、再度 **Scan / Refresh** をクリックしてください。外部でアセットやインポーターを編集した後も再スキャンしてください。

## 2. 表の読み方

表ではアセットパスでテクスチャの重複を除き、複数の参照があっても同じインポーターへの処理を繰り返さないようにします。検索フィールドによる絞り込み、列の並べ替え、選択前のアセットパスの確認ができます。サムネイルをクリックすると Project ウィンドウでテクスチャがハイライトされます。行のコンテキストメニューから、Inspector でのアセット選択やパスのコピーもできます。

| 列 | 意味 |
| --- | --- |
| **Apply** | 提案するバッチの対象としてチェックされているかどうか。チェックだけでは何も書き込みません。 |
| **Texture / source dimensions** | 選択可能な上限を制限するために使用する元画像のサイズ。 |
| **Asset path** | 編集対象となる共有テクスチャアセット。 |
| **Loaded now** | 現在 Editor に読み込まれているサイズとグラフィックス形式。選択したプラットフォームの出力と同じとは限りません。 |
| **Caps: D / S / A** | Default、Standalone、Android の設定。`*` は明示的なプラットフォームオーバーライドを示します。 |
| **Chosen target now** | 選択した対象で実際に有効な上限と、推定サイズ。 |
| **Current GPU est.** | 読み込み済みテクスチャ全体の割り当て量の推定値。常駐メモリの実測値ではありません。 |
| **Proposed cap** | 要求する解像度上限。まだ適用されていません。 |
| **Proposed GPU est. / Savings est.** | 現在読み込まれている形式を代用して計算した、提案後の割り当て量／削減量の推定値。 |
| **Safety / precedence** | ロック、プラットフォーム設定による優先適用、オーバーライドの注意。適用前に確認してください。 |

### メモリ推定値の解釈

このツールが推定するのは GPU への全体の割り当て量であり、プロファイラーが示す常駐メモリの実測値ではありません。ディスク上の元ファイルのサイズとも異なります。インポート後のテクスチャを小さくすると、見た目の品質も下がる場合があります。許容できる品質かどうかを推定値が判断してくれるわけではありません。

対象と提案後の推定には、Editor に読み込まれたグラフィックス形式を再利用します。実際の出力は、プラットフォーム固有の圧縮、実機での形式のフォールバック、ストリーミング、スプライトアトラスへのパッキング、インポーターの丸め処理によって異なる場合があります。**Android の提案値は現在の形式を代用した目安であり、Android メモリの実測値ではありません。** プラットフォームの上限を指定しても、インポート後のサイズが厳密にその値になるとは限りません。

FPS 向上は保証しません。フレームレートの改善をこれらの変更によるものと判断する前に、実際のビルドをプロファイリングし、対象ハードウェアで確認してください。

### テクスチャがロックされる理由

ロックされた行は、インポーターの上限変更から意図的に除外されます。主な理由は次のとおりです。

- スプライト／アトラスの入力: インポーターの変更が、パッキング、スライス、UI レイアウトに影響する可能性があります。
- 生成されたライティング、反射、ライトマップなどのアセット: 生成元のワークフローを使用してください。
- パッケージ内、組み込み、一時的なテクスチャ: `Assets` 内の通常の編集可能なアセットではありません。
- 対応する `TextureImporter` のない、埋め込み／サブアセットやネイティブ／生成アセット。
- Render Texture、配列、Cubemap など、未対応の非 2D インポーター形状。
- アセット／メタデータが読み取り専用、元画像サイズが不明、または選択可能な最小上限よりサイズが小さい場合。
- 選択したプラットフォームが対応していない明示的な形式を継承している場合。この上限変更ツールに修正を任せず、Unity の Inspector で対応する形式を意図的に選択してください。

ツールで編集可能にするためだけにパッケージ内／生成アセットを移動したり、ロックを回避したりしないでください。管理元のシステムが再生成する場合や、異なる設定を必要とする場合があります。

## 3. チェックを入れて変更を提案する

1. 変更したい編集可能なテクスチャにチェックを入れます。**Select visible editable** は、現在の表のフィルターに一致する編集可能な行をチェックします。便利な選択機能であり、表示されたすべてのテクスチャを縮小すべきという推奨ではありません。**Clear selection** でチェックを解除できます。
2. 各行の **Proposed cap** を変更するか、一括設定用のサイズを選んで **Propose for checked** をクリックします。
3. ステータスレポートでスキップされた行を確認し、各提案を確認します。

選択可能な上限は 32 ～ 16384 ピクセルで、元画像サイズと現在有効な上限によって制限されます。optimizer は有効な上限を引き上げたり、元画像のピクセルを拡大したりしません。一括提案で要求した上限が行の許容範囲を超える場合、その行はスキップされます。有効な上限と同じ値を選んでも、不必要なオーバーライドの作成やインポーターへの書き込みは行いません。

提案してもアセットは変更されません。チェックマークや推定値の減少は、適用の確定を意味しません。

## 4. プレビューしてから適用する

**Preview Apply checked...** をクリックします。変更対象がなければ、その旨を表示し、バックアップの作成やアセットのインポートは行いません。

プレビューには、対象テクスチャアセットの名前をすべて含む一覧、選択した対象、変更前後の保存上限、プラットフォームオーバーライドの注意、バックアップ先が表示されます。特に、既存のオーバーライドがある状態で Default を編集する場合や、新しいプラットフォームオーバーライドを有効にする場合は、よく確認してください。

- **Cancel — no changes** は適用せずにプレビューを閉じます。
- **Apply these named resolution caps** が、明示的に書き込みを実行する操作です。

インポーターへの変更を書き込む前に、次の場所へ永続的なバッチ記録を保存します。

```text
<your-project>/UserSettings/ProkjsTextureOptimizerBackups/
```

変更のたびに、アセット／インポーターの状態を再確認します。スキャンやプレビュー以降に変更された場合は、上書きせずに計画を無効と判定したり、競合として扱ったりします。Unity が対象テクスチャをそれぞれ再インポートするため、時間がかかる場合があります。

バッチは、すべて成功するかすべて取り消すかのトランザクションではありません。キャンセル、エラー、中断により、一部だけが適用され、残りが未変更になる場合があります。項目ごとの記録と結果レポートで進行状況を確認できます。実行中のバッチをキャンセルしても、それ以前に適用された項目が元に戻るとは考えないでください。バックアップを保管してください。

適用後は件数とメッセージを読み、再スキャンしてプロジェクト全体の品質を確認してください。コミット前にバージョン管理の差分を確認します。このツールは元画像のピクセルを書き換えませんが、インポーターのメタデータ変更はアセットのすべての参照元に影響します。

## 5. 最新バッチを復元する

1. optimizer をインストールした状態で、バックアップディレクトリも保管しておきます。
2. **Restore Last Batch...** をクリックします。
3. 対象項目の名前とバックアップ先を確認します。
4. **Restore safe matching entries** をクリックし、optimizer が変更した状態と現在も安全に一致する項目を復元します。
5. レポートを読み、再スキャンして、プロジェクトとバージョン管理の差分を確認します。

復元では、安全に一致する項目について、記録された対象の以前の解像度／オーバーライド設定を復旧します。元画像を置き換えたり、無関係なプロジェクト変更を戻したり、後から行われた編集を古いスナップショットに強制的に戻したりはしません。すでに元の状態と一致しているインポーターは、復元済みとして扱います。

### 競合は保護機能であり、上書きしてよいという意味ではありません

元画像の変更、後から行われたインポーター編集、アセットの欠落／ロック、中断したインポートの状態が確定できない場合などは、復元できないことがあります。競合する項目はスキップされ、手動で確認できるようバックアップ内に残ります。最大サイズとは無関係な変更でも、後から圧縮やプラットフォーム設定を変更すると競合になる場合があります。

レポートとバックアップを保管してください。アセットの現在の Inspector 設定とバージョン管理履歴を、意図した状態と比較してください。関連する `.meta` の変更を、ご自身のバージョン管理の手順で差し戻すか、Inspector で意図的に設定を編集します。強制的に復元するために、バックアップのハッシュを編集したり、安全機構を取り除いたりしないでください。

### バックアップの制限

- バックアップは `UserSettings/ProkjsTextureOptimizerBackups/` に**プロジェクトごとにローカル保存**されます。インポーターを復元するためのデータであり、元画像のコピーではありません。
- バージョン管理やバックアップ設定で `UserSettings` が除外されている場合があります。チームメンバーや別のコンピューターにも記録があるとは考えないでください。
- ウィンドウで扱えるのは**最後に保存されたバッチだけ**であり、履歴の選択機能ではありません。そのバッチを復元しても、前のバッチが次の自動的な取り消し対象として現れるわけではありません。複数バッチにわたる復旧にはバージョン管理履歴を残してください。
- 記録は元のプロジェクトの場所に紐づいています。プロジェクトを移動／クローンしても、記録が持ち運び可能な復旧ファイルになるわけではありません。その場合はバージョン管理またはプロジェクトのバックアップを使用してください。
- ドメインリロードにより、開いているプレビューが無効になる場合があります。何かが適用済みだと思い込まず、プレビューを作成し直してください。

## 更新・移行・アンインストール

インストール方法は一つだけ使用してください。方法を切り替える場合は、既存のパッケージ／スクリプトを元のインストール方法に対応した手順で削除してから、別のコピーを追加します。ツールの削除時にテクスチャアセットやそのメタデータを削除しないでください。

- **UPM:** Unity Package Manager で `com.prokjs.texture-optimizer` を削除します。
- **VCC:** VCC のプロジェクトのパッケージ管理から削除します。
- **`.unitypackage`:** インポートしたツールのフォルダー `Assets/prokjs/TextureOptimizer` を削除します。

**アンインストールしてもテクスチャの上限は元に戻りません。** 先に必要なバッチを復元するか、バージョン管理でインポーターのメタデータを差し戻してください。ローカルのバックアップ記録はインストールされたツールとは別のもので、パッケージを削除しても自動的には削除されません。不要になるまで保管してください。

古い単体版を削除する際は、任意のテクスチャアセットではなく、古い optimizer スクリプトを探してください。backend／window／preview のクラスが重複すると、パッケージ内にあるコピーが一つだけでもコンパイルエラーになる場合があります。

## トラブルシューティング

| 症状 | 対処方法 |
| --- | --- |
| 型やメニューの重複エラー | `.unitypackage`／UPM／VCC の二重インストールや、古い単体版スクリプトのコピーを確認します。一つのインストールだけを残してください。 |
| UI／`UnityEngine.UI` の参照エラー | 特に `.unitypackage` のインポートでは、Unity UI（`com.unity.ugui`）がインストールされていることを確認します。 |
| シーンスキャンに期待したテクスチャがない | 読み込み済みシーン、選択、非アクティブなオブジェクトの設定、対応する参照範囲を確認します。Folder／ProjectAssets の一覧も試してください。シーンスキャンにないことは、未使用である証拠にはなりません。 |
| Default の引き下げがプラットフォームに反映されない | `*` のオーバーライドマークを確認します。明示的なプラットフォームオーバーライドが Default より優先されます。意図したプラットフォームを対象に選択し、プレビューを確認してください。 |
| 提案がスキップされる、または大きい上限を選べない | ツールが提供するのは、元画像／有効な上限の範囲内で対応する引き下げだけです。意図的に引き上げる場合は Unity の Inspector を使用してください。 |
| スキャン後に変更されたインポーターがプレビューで拒否される | 再スキャンして、新しい提案を確認します。古いプレビューを再利用しないでください。 |
| バックアップがない、または最新バッチが想定と異なる | このプロジェクトのローカルバックアップディレクトリと、レポート内のパスを確認します。UI は履歴ブラウザーではありません。古い変更の復旧にはバージョン管理履歴を使用します。 |
| 適用／復元が途中まで、またはキャンセルされた | 項目の件数／メッセージを読み、バックアップを保管して現在の状態を確認します。完了済みの項目は自動的には元に戻りません。 |
| 復元の競合 | 後から行った編集を保護してください。バックアップとバージョン管理履歴を手動で確認し、無理にバックアップと一致させないでください。 |

サポートが必要な場合は、パッケージのバージョン、正確な Unity バージョン、インストール方法、Scope／対象、メッセージ、再現手順を添えて [Issue を作成](https://github.com/prokjs/texture-optimizer/issues)してください。共有前に、バックアップ記録やログに非公開のパスが含まれていないか確認してください。テストした Unity バージョンとワークフローの正確な範囲は、[README のリリース検証範囲](../README.ja.md#リリースの検証範囲)を参照してください。実機のメモリやパフォーマンスを測定したという主張はしていません。
