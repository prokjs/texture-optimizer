# prokjs's VRChat World Optimizer v1.1.0 사용 설명서

[EN](user-guide.md) · [한국어](user-guide.ko.md) · [日本語](user-guide.ja.md)

> **Unity 2022.3.22f1을 사용하는 VRChat 프로젝트를 위해 제작되었습니다. 다른 Unity 버전은 테스트하지 않았으며 호환되지 않을 수 있습니다.**

VRChat 프로젝트를 대상으로 제작했지만 패키지 자체는 VRChat SDK에 의존하지 않습니다.

텍스처, LOD 분석/생성, 오클루전/바닥 그림자 준비를 제공하는 Editor 전용 통합 창입니다. 창을 열어도 스캔/적용/베이크하지 않습니다. 패키지 ID는 `com.prokjs.texture-optimizer`를 유지합니다.

설치 방법, 요구 사항 및 특정 버전으로 고정된 패키지 URL은 [README](../README.ko.md)를 참고하세요. 한 가지 설치 방법으로 한 사본만 설치하세요. 설치 전에 기존 독립형 최적화 스크립트를 제거하세요.

## 통합 작업: LOD & Analysis

1. Edit Mode에서 씬/에셋을 저장하고 백업한 후 **LOD & Analysis**를 스캔합니다. 권장 사항은 정적 추정치이며 실제 드로콜, GPU 시간, 메모리 상주량이나 FPS 개선의 증거가 아닙니다.
2. 후보와 제외 사유를 개별 검토합니다. 권장 자동 생성은 지원하는 내장 셰이더의 고정 불투명 MeshRenderer용입니다. 픽업, Udon 제어 대상, 스킨드 메시, 머티리얼/프로퍼티 오버라이드, 안전하지 않은 계층 및 베이크된 라이트맵 대체를 제외합니다. 잠금을 우회하지 마세요.
3. 기존 LODGroup은 Inspector 미리보기에서 레벨/전환을 확인합니다. 이는 메시 재생성이 아닙니다.
4. 적격 후보의 감소율을 정하고 대상 이름이 표시된 미리보기를 검토한 후 적용합니다. 비율은 **제거할 정점 비율**이며 남는 삼각형 비율이 아닙니다. 토폴로지 보존 때문에 목표에 정확히 도달하지 못할 수 있습니다.
5. LOD0 원본 메시를 유지하고 새 축소 `.asset`을 `Assets/prokjs/WorldOptimizerGenerated`에 캐시합니다. 원본 메시/UV, 머티리얼 에셋, 콜라이더는 다시 쓰지 않습니다. 실루엣/UV 음영/전환을 직접 확인하세요. 자동 품질 보장은 없습니다.
6. Undo 또는 해당 배치 복원을 사용합니다. 생성된 메시 에셋은 Undo와 저장된 참조 보호를 위해 **복원 후에도 보존**합니다. 복원은 에셋 정리가 아닙니다. 씬 배치 기록은 `UserSettings/ProkjsWorldOptimizerBatches`에 저장하며 별도의 씬/소스 관리 백업도 필요합니다.

## 통합 작업: Occlusion & Shadows

스캔 후 적합한 고정 불투명 후보를 검토하고 미리보기 후 정적 플래그 준비를 명시적으로 적용합니다. 오클루더/오클루디 플래그는 **범용 런타임 컬링이 아니며** 즉시 오브젝트를 숨기지 않습니다. 별도의 Unity 오클루전 베이크 후 결과를 확인하세요. 기존 런타임 타프 컨트롤러는 변경하지 않습니다.

바닥 그림자 준비에는 적합한 **기존 UV2/GI 설정**이 필요합니다. UV2를 생성하거나 실시간 조명을 변환하거나 바닥만 별도 베이크하지 않습니다. 조명 베이크는 별도 확인을 거치는 **씬 전체** Unity 작업이며 오래 걸릴 수 있습니다. 씬 조명 설정과 영향받는 전체 내용을 먼저 검토하고 필요하면 취소를 요청하세요. 스캔/플래그 준비로 베이크가 시작되지 않습니다.

Undo/배치 복원은 기록한 씬 플래그를 복원하며 **베이크된 조명 데이터는 복원하지 않습니다.** 베이크는 공유 씬 조명 출력을 대체할 수 있으므로 먼저 씬/조명 에셋을 백업하고 결과를 확인하세요.

## 네이티브 Texture2D `.asset` 예외

파일의 유일한 오브젝트인 편집 가능한 독립형 주 Texture2D `.asset`은 RGBA32/DXT1/DXT5일 때 **Default만** 축소할 수 있습니다. 이는 임포터 상한이 아닌 **픽셀 자체의 리샘플링**으로 모든 플랫폼에 공유됩니다. PNG/JPG 등 임포트 원본 픽셀은 변경하지 않습니다.

GUID/로컬 ID, 포맷, 색 공간, 샘플러/스트리밍 설정과 밉맵 유무를 유지하며 밉 체인은 다시 생성합니다. 쓰기 전에 원래 `.asset` 바이트를 저장합니다. 저장되지 않은 변경이 있는 에셋, 내장/하위 에셋, 패키지/편집 불가, 메타데이터 누락, 미지원 포맷, 생성 조명/반사 에셋은 잠깁니다. 최소 상한은 32입니다.

네이티브 복원은 GUID/경로/메타데이터/적용 후 내용 해시와 바이트 백업이 일치해야 합니다. 이동/대체/이후 편집 또는 중단된 저장의 불확실한 상태는 덮어쓰지 않습니다. 충돌 시 백업을 보존하고 소스 관리를 사용하세요. 제거만으로 픽셀이나 상한이 복원되지는 않습니다.

아래는 **Textures** 작업 설명이며 임포터 전용 설명에는 위 네이티브 예외가 우선합니다.

## 시작하기 전에

1. 작업 내용을 저장하고, 텍스처 원본 파일과 `.meta` 파일을 포함하여 프로젝트를 커밋하거나 백업합니다.
2. 버전 관리 시스템에서 체크아웃이나 잠금을 사용한다면 먼저 텍스처와 해당 `.meta` 파일을 편집 가능하게 만듭니다.
3. Play Mode가 아닌 상태에서 작업합니다. 임포터 변경 적용 및 복원에는 Edit Mode가 필요합니다.
4. 임포트된 텍스처 크기를 줄이기 위해 어느 정도의 품질 저하를 감수할지 결정합니다. 프로젝트 전체가 아니라 중요도가 낮은 몇 개의 텍스처로 시작하세요.

**텍스처를 공유하면 변경 결과도 공유합니다.** 오브젝트 하나를 선택해도 해당 텍스처의 전용 사본이 만들어지지 않습니다. 편집한 텍스처를 사용하는 다른 모든 씬, 프리팹 및 머티리얼에도 새 임포트 상한이 적용됩니다.

텍스처 변경은 Unity Undo 복원을 보장하지 않습니다. 텍스처 배치 백업과 소스 관리를 사용하세요. LOD/정적 플래그 씬 변경은 별도의 Undo/배치 복원을 사용합니다.

## 1. 스캔할 범위 선택

**Tools → prokjs → VRChat World Optimizer**에서 **Textures** 탭을 열고 **Scope**를 선택합니다.

| Scope | 수집하는 대상 |
| --- | --- |
| **LoadedScenes** | 현재 로드된 씬의 오브젝트에 있는 지원되는 참조와 씬의 스카이박스 머티리얼. 다른 씬을 열지는 않습니다. |
| **SelectedObjects** | 선택한 씬 오브젝트 또는 프리팹 에셋과 그 하위 오브젝트. 스캔 전에 하나 이상 선택하세요. |
| **Folder** | `Assets` 아래에서 선택한 폴더와 하위 폴더의 텍스처 에셋. |
| **ProjectAssets** | `Assets` 아래의 텍스처 에셋. 의도적으로 `Packages`는 제외합니다. |

씬/선택 탐색은 렌더러 머티리얼, Terrain 머티리얼/레이어 텍스처, Unity UI 그래픽의 텍스처/머티리얼 및 라이트 쿠키를 읽습니다. 참조된 머티리얼의 텍스처 프로퍼티를 검사합니다. **Include inactive objects**는 오브젝트 기반 스캔에 비활성 오브젝트를 포함할지 결정합니다.

이는 완전한 빌드 의존성 분석이 아닙니다. 아바타 애니메이션 클립, 임의의 스크립트, Addressables 로딩에서만 참조되는 머티리얼이나 텍스처 또는 모든 커스텀 컴포넌트를 찾아낸다고 보장하지 않습니다. 폴더/프로젝트 스캔은 에셋 목록이며 사용 중이거나 사용하지 않는다는 증거가 아닙니다.

**Edit cap for**를 선택합니다.

- **Default:** 기본 최대 텍스처 크기를 변경합니다. 명시적인 플랫폼 오버라이드가 우선하므로 Standalone 또는 Android 출력은 달라지지 않을 수 있습니다.
- **Standalone:** Standalone 상한을 변경합니다. 활성화된 오버라이드가 없으면 변경된 상한을 적용할 때 Default에서 상속한 설정을 사용하여 오버라이드를 활성화할 수 있습니다. 미리보기 안내를 읽으세요.
- **Android:** Android에 같은 상한/오버라이드 작업 흐름을 적용합니다. Android 기기를 측정하거나 Android 압축 포맷을 자동으로 선택하지는 않습니다.

**Scan / Refresh**를 클릭합니다. 현재 상태의 스냅샷을 읽을 뿐 임포트 설정은 변경하지 않습니다. 스캔을 취소하면 일부 목록만 남을 수 있으며 보고서에 표시됩니다. 전체 목록이 필요하면 다시 스캔하세요.

범위, 대상 또는 비활성 오브젝트 옵션을 바꾸면 기존 스냅샷이 오래된 상태가 됩니다. 새 적용 미리보기를 만들기 전에 **Scan / Refresh**를 다시 클릭하세요. 외부에서 에셋/임포터를 편집한 후에도 다시 스캔하세요.

## 2. 표 읽기

표는 에셋 경로별로 텍스처 중복을 제거하므로 여러 곳에서 참조해도 같은 임포터 작업이 반복되지 않습니다. 검색 필드로 필터링하고 열을 정렬하며, 선택 전에 에셋 경로를 확인할 수 있습니다. 썸네일을 클릭하면 Project 창에서 해당 텍스처가 강조됩니다. 행의 컨텍스트 메뉴에서는 Inspector에 표시할 에셋을 선택하거나 경로를 복사할 수 있습니다.

| 열 | 의미 |
| --- | --- |
| **Apply** | 제안 배치에 포함하도록 체크했는지 표시합니다. 체크만으로는 아무것도 기록하지 않습니다. |
| **Texture / source dimensions** | 허용 상한을 제한하는 데 사용하는 원본 크기. |
| **Asset path** | 편집 대상인 공유 텍스처 에셋. |
| **Loaded now** | 현재 Editor에 로드된 크기와 그래픽스 포맷. 선택한 플랫폼의 출력과 반드시 같지는 않습니다. |
| **Caps: D / S / A** | Default, Standalone, Android 설정. `*`는 명시적인 플랫폼 오버라이드를 나타냅니다. |
| **Chosen target now** | 선택한 대상의 유효 상한과 예상 크기. |
| **Current GPU est.** | 로드된 텍스처의 전체 할당량 추정치. 실제 상주량 측정값이 아닙니다. |
| **Proposed cap** | 요청한 해상도 상한. 아직 적용되지 않았습니다. |
| **Proposed GPU est. / Savings est.** | 현재 로드된 포맷을 제안의 대용값으로 사용한 추정치. |
| **Safety / precedence** | 잠금, 플랫폼 설정의 우선 적용 및 오버라이드 안내. 적용 전에 읽으세요. |

### 메모리 추정치 해석

도구는 전체 GPU 할당량을 추정하며, 프로파일러가 읽은 실제 메모리 상주량을 표시하지 않습니다. 디스크의 원본 파일 크기는 별개의 값입니다. 임포트된 텍스처를 줄이면 화질도 나빠질 수 있습니다. 추정치는 허용 가능한 품질을 대신 판단해 주지 않습니다.

대상 및 제안 추정치에도 Editor에 로드된 그래픽스 포맷을 재사용합니다. 플랫폼별 압축, 기기의 포맷 폴백, 스트리밍, 스프라이트 아틀라스 패킹, 임포터의 크기 반올림 때문에 실제 출력은 달라질 수 있습니다. **Android 제안은 현재 포맷을 이용한 대용 추정이며 Android 메모리 측정값이 아닙니다.** 플랫폼 상한은 정확한 임포트 크기를 보장하지 않습니다.

FPS 향상을 보장하지 않습니다. 프레임 속도 개선을 이 변경의 효과로 판단하기 전에 실제 빌드를 프로파일링하고 대상 하드웨어에서 확인하세요.

### 텍스처가 잠기는 이유

잠긴 행은 의도적으로 임포터 상한 변경에서 제외됩니다. 대표적인 이유는 다음과 같습니다.

- 스프라이트/아틀라스 입력: 임포터 변경이 패킹, 슬라이싱 및 UI 레이아웃에 영향을 줄 수 있습니다.
- 생성된 조명, 반사, 라이트맵 등의 에셋: 해당 에셋을 생성하는 작업 흐름을 사용하세요.
- 패키지, 내장 또는 임시 텍스처: `Assets` 아래의 일반적인 편집 가능 에셋이 아닙니다.
- 내장 하위 에셋 및 지원하지 않는 네이티브/생성 에셋. 지원하는 독립형 Texture2D 예외는 위 설명을 참고하세요.
- Render Texture, 배열, 큐브맵 등 지원하지 않는 비 2D 임포터 형태.
- 읽기 전용 에셋/메타데이터, 원본 크기 정보 누락 또는 제공하는 최소 상한보다 작은 크기.
- 선택한 플랫폼에서 지원하지 않는 명시적 포맷을 상속한 경우. 이 상한 도구에 수정을 맡기지 말고 Unity Inspector에서 지원되는 포맷을 직접 선택하세요.

도구에서 편집하게 만들 목적으로 패키지/생성 에셋을 옮기거나 잠금을 우회하지 마세요. 관리 시스템이 다시 생성하거나 다른 설정을 요구할 수 있습니다.

## 3. 체크하고 제안하기

1. 변경하려는 편집 가능 텍스처를 체크합니다. **Select visible editable**은 현재 표 필터와 일치하는 편집 가능 행을 체크합니다. 편의 기능일 뿐 보이는 텍스처를 모두 줄이라는 권장이 아닙니다. **Clear selection**은 체크를 해제합니다.
2. 각 행의 **Proposed cap**을 변경하거나 배치 크기를 선택하고 **Propose for checked**를 클릭합니다.
3. 상태 보고서에서 건너뛴 행을 확인하고 각 제안을 검토합니다.

제공하는 상한은 32~16384픽셀이며 원본 크기와 유효 상한의 제한을 받습니다. 도구는 유효 상한을 높이거나 원본 픽셀을 확대하지 않습니다. 요청한 상한이 허용 범위를 벗어나면 해당 행의 배치 제안을 건너뜁니다. 유효 상한과 같은 값을 선택해도 불필요한 오버라이드나 임포터 기록을 만들지 않습니다.

제안은 에셋을 변경하지 않습니다. 체크 표시나 낮아진 추정치가 적용 동의를 의미하지는 않습니다.

## 4. 미리보기 후 적용

**Preview Apply checked...**를 클릭합니다. 변경할 내용이 없으면 백업을 만들거나 에셋을 임포트하지 않고 그 사실을 알립니다.

미리보기에는 전체 텍스처 에셋 이름, 선택한 대상, 저장된 이전/새 상한, 플랫폼 오버라이드 안내 및 백업 경로가 나옵니다. 기존 오버라이드가 있는 상태에서 Default를 편집하거나 새 플랫폼 오버라이드를 활성화할 때 특히 주의해서 읽으세요.

- **Cancel — no changes**는 적용하지 않고 미리보기를 닫습니다.
- **Apply these named resolution caps**가 실제 변경을 기록하는 단계입니다.

임포터 변경을 기록하기 전에 다음 위치에 지속적으로 보관되는 배치 기록을 저장합니다.

```text
<your-project>/UserSettings/ProkjsTextureOptimizerBackups/
```

각 변경 전에 에셋/임포터 상태를 다시 확인합니다. 스캔 또는 미리보기 이후 변경된 내용은 덮어쓰는 대신 계획을 무효화하거나 충돌을 발생시킬 수 있습니다. Unity가 영향을 받는 텍스처를 각각 재임포트하므로 시간이 걸릴 수 있습니다.

배치는 전부 적용되거나 전부 취소되는 트랜잭션이 아닙니다. 취소, 오류 또는 중단으로 일부 항목만 적용되고 나머지는 그대로 남을 수 있습니다. 항목별 기록과 결과 보고서에 진행 상태가 표시됩니다. 실행 중인 배치를 취소하면 이전 항목까지 되돌아간다고 생각하지 마세요. 해당 백업을 보관하세요.

적용 후 보고서를 읽고 다시 스캔하여 모든 사용처의 품질과 소스 관리 변경을 확인하세요. 임포트 이미지 원본 픽셀은 유지하지만 메타데이터 변경은 모든 사용처에 영향을 줍니다. 지원하는 네이티브 `.asset`은 픽셀 자체를 축소합니다.

## 5. 마지막 배치 복원

1. 도구를 설치된 상태로 유지하고 백업 디렉터리도 보관합니다.
2. **Restore Last Batch...**를 클릭합니다.
3. 표시된 항목 이름과 백업 위치를 확인합니다.
4. **Restore safe matching entries**를 클릭하여 도구가 관리한 상태와 안전하게 일치하는 항목을 복원합니다.
5. 보고서를 읽고 다시 스캔한 뒤 프로젝트와 소스 관리 변경 내역을 검토합니다.

임포트 텍스처는 안전하게 일치하는 항목의 이전 해상도/오버라이드 설정을 복구하며 원본 이미지나 무관한 편집은 되돌리지 않습니다. 이미 원래 설정인 임포터는 복원 완료로 취급합니다. 네이티브 텍스처는 모든 식별/내용 검사가 일치할 때 원래 `.asset` 바이트를 복구합니다.

### 충돌은 덮어쓰기 허가가 아니라 보호 장치입니다

원본 이미지 변경, 이후 임포터 편집, 누락/잠긴 에셋 또는 중단된 임포트의 불확실한 상태 때문에 복원하지 못할 수 있습니다. 충돌 항목은 건너뛰며 수동 검토할 수 있도록 백업에 남깁니다. 최대 크기와 관련 없는 변경이라도 이후 압축 또는 플랫폼 설정 변경은 충돌이 될 수 있습니다.

보고서와 백업을 보관하세요. 현재 Inspector 설정과 소스 관리 이력을 원래 의도와 비교한 뒤, 사용하는 버전 관리 절차로 해당 `.meta` 변경을 되돌리거나 Inspector에서 의도적으로 설정을 편집하세요. 강제로 복원하려고 백업 해시를 수정하거나 안전장치를 제거하지 마세요.

### 백업의 제한

- 백업은 `UserSettings/ProkjsTextureOptimizerBackups/`의 프로젝트별 로컬 데이터입니다. 임포트 텍스처는 원본 이미지가 아닌 임포터 복원 데이터를 저장하고, 지원하는 네이티브 텍스처는 원본 `.asset` 바이트도 저장하므로 모두 보존하세요.
- 버전 관리나 백업 설정에서 `UserSettings`를 제외할 수 있습니다. 팀원이나 다른 컴퓨터에도 기록이 있다고 가정하지 마세요.
- 창에서는 이력 선택기가 아닌 **마지막으로 저장한 배치만** 제공합니다. 이를 복원해도 이전 배치가 다음 자동 되돌리기 단계로 나타나지 않습니다. 여러 배치를 복구하려면 소스 관리 이력을 보관하세요.
- 기록은 원래 프로젝트 위치에 연결됩니다. 프로젝트를 옮기거나 복제해도 기록이 이식 가능한 복구 파일이 되지는 않습니다. 이 경우 소스 관리 또는 프로젝트 백업을 사용하세요.
- 도메인 리로드로 열린 미리보기가 무효화될 수 있습니다. 적용되었다고 가정하지 말고 미리보기를 다시 만드세요.

## 업데이트, 이전 및 제거

한 가지 설치 방법만 사용하세요. 설치 방법을 바꾸려면 기존 패키지/스크립트를 원래 설치 방식에 맞게 제거한 뒤 다른 사본을 추가하세요. 도구를 제거하면서 텍스처 에셋이나 메타데이터를 삭제하지 마세요.

- **UPM:** Unity Package Manager에서 `com.prokjs.texture-optimizer`를 제거합니다.
- **VCC:** VCC의 프로젝트 패키지 관리에서 패키지를 제거합니다.
- **`.unitypackage`:** 임포트한 도구 폴더 `Assets/prokjs/TextureOptimizer`를 제거합니다.

**제거해도 텍스처 상한은 복원되지 않습니다.** 먼저 원하는 배치를 복원하거나 소스 관리에서 임포터 메타데이터를 되돌리세요. 로컬 백업 기록은 설치된 도구와 별개이며 패키지 제거 시 자동으로 삭제되지 않습니다. 더 이상 필요하지 않을 때까지 보관하세요.

기존 독립형 버전을 제거할 때는 임의의 텍스처 에셋이 아니라 이전 최적화 스크립트를 찾으세요. 패키지 안에 사본이 하나뿐이어도 백엔드/창/미리보기 클래스가 중복되면 컴파일 오류가 발생할 수 있습니다.

## 문제 해결

| 증상 | 조치 |
| --- | --- |
| 중복 타입 또는 중복 메뉴 오류 | `.unitypackage`/UPM/VCC 중복 설치와 기존 독립형 스크립트 사본을 확인하세요. 한 설치만 남기세요. |
| UI/`UnityEngine.UI` 참조 오류 | 특히 `.unitypackage` 임포트 시 Unity UI (`com.unity.ugui`)가 설치되어 있는지 확인하세요. |
| 씬 스캔에서 예상한 텍스처가 보이지 않음 | 로드된 씬, 선택 항목, 비활성 오브젝트 설정 및 지원되는 참조 범위를 확인하세요. Folder/ProjectAssets 목록을 사용해 보세요. 씬 스캔에 없다는 이유만으로 사용하지 않는 텍스처라고 판단할 수 없습니다. |
| Default 축소가 특정 플랫폼에 영향을 주지 않음 | `*` 오버라이드 표시를 확인하세요. 명시적인 플랫폼 오버라이드가 Default보다 우선합니다. 원하는 플랫폼 대상을 선택하고 미리보기를 확인하세요. |
| 제안을 건너뛰거나 더 큰 상한을 선택할 수 없음 | 원본/유효 상한 내에서 지원되는 축소만 제공합니다. 의도적으로 크기를 늘리려면 Unity Inspector를 사용하세요. |
| 스캔 이후 변경된 임포터 때문에 미리보기가 거부됨 | 다시 스캔하고 새 제안을 검토하세요. 오래된 미리보기를 재사용하지 마세요. |
| 백업이 없거나 예상과 다른 마지막 배치가 표시됨 | 이 프로젝트의 로컬 백업 디렉터리와 보고서의 경로를 확인하세요. UI는 이력 탐색기가 아닙니다. 이전 변경은 소스 관리 이력으로 복구하세요. |
| 적용 또는 복원이 일부 완료되거나 취소됨 | 항목 개수/메시지를 읽고 백업을 유지하며 현재 상태를 확인하세요. 완료된 항목은 자동으로 롤백되지 않습니다. |
| 복원 충돌 | 이후 편집 내용을 보존하세요. 백업과 소스 관리 이력을 수동으로 검토하고 백업을 강제로 맞추지 마세요. |

지원이 필요하면 패키지 버전, 정확한 Unity 버전, 설치 방법, 범위/대상, 메시지 및 재현 절차를 포함하여 [이슈를 등록](https://github.com/prokjs/texture-optimizer/issues)하세요. 공유 전에 백업 기록과 로그에 비공개 경로가 있는지 확인하세요. 정확한 테스트 Unity 버전과 작업 흐름은 [영문 README의 릴리스 검증](../README.md#release-verification)을 참고하세요. 기기 메모리 또는 성능 측정 결과를 주장하지 않습니다.
