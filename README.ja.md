# prokjs's VRChat World Optimizer — v1.1.0

**言語:** [EN](README.md) · [한국어](README.ko.md) · 日本語

> **Unity 2022.3.22f1 を使用する VRChat プロジェクト向けに作成されています。ほかの Unity バージョンではテストされておらず、互換性がない可能性があります。**

**変更する前に、テクスチャの解像度上限を確認しましょう。** prokjs が独自に開発したスタンドアロンの Unity Editor ツールです。インポート済みテクスチャを探し、推定 GPU メモリ割り当て量を比較し、復元手段を確保したうえでインポーターの解像度上限を意図的に引き下げられます。

**Tools → prokjs → VRChat World Optimizer** から開きます。**Textures**、**LOD & Analysis**、**Occlusion & Shadows** の統合ウィンドウです。開いたりスキャンしたりするだけで変更やベイクは実行されません。

- 読み込み済みシーン、選択したオブジェクト、Assets 内のフォルダー、または Assets 内のプロジェクト全体のテクスチャアセットをスキャンできます。
- 元画像のサイズ、読み込み済みのサイズと形式、Default / Standalone / Android の上限、安全上の制限を一つの表で確認できます。
- テクスチャにチェックを入れて小さい上限を提案し、適用前に対象アセット名をすべて含むプレビューを確認できます。
- プロジェクトごとのバックアップ記録を保存し、最新バッチから状態が安全に一致する項目を復元できます。

## 必要環境

- **Unity 2022.3.22f1**。独立したクリーンなプロジェクトにローカル UPM インストールした環境でテストしています。
- Unity UI（`com.unity.ugui`）。UPM/VCC インストールではパッケージの依存関係として宣言されています。`.unitypackage` でインストールする場合は、Package Manager で Unity UI が利用可能であることを確認してください。
- 編集可能なテクスチャアセットとその `.meta` ファイル。バージョン管理システムでファイルがロックされる場合は、先にチェックアウトしてください。

VRChat プロジェクトを想定していますが、パッケージは VRChat SDK に依存しません。インストールや使用に VRChat SDK、Udon、そのほかのアバター／ワールド用ツールは必要ありません。

### バージョンとアップグレード

**1.1.0** は既存ツールの拡張です。リポジトリ `prokjs/texture-optimizer`、パッケージ `com.prokjs.texture-optimizer`、名前空間 `Prokjs.TextureOptimizer`、既存のテクスチャバックアップ先を維持します。過去の 1.0.0 のテクスチャ検証は、新しい LOD／照明機能の検証ではありません。

## インストール — 方法は一つだけ選択

`.unitypackage` のインポートと UPM または VCC によるインストールを併用しないでください。以前、単体版の optimizer スクリプトをプロジェクトにコピーしていた場合は、インストール前に古いコピーを削除してください。型やメニュー項目が重複するとコンパイルできなくなる場合があります。移行前に必要なバックアップを保管してください。

### 方法 1: GitHub リリースの `.unitypackage`

1. [v1.1.0 リリース](https://github.com/prokjs/texture-optimizer/releases/tag/v1.1.0)を開きます。
2. **Assets** から **`prokjs-texture-optimizer-1.1.0.unitypackage`** をダウンロードします。「Source code」の ZIP/TAR は Unity インポート用ではありません。
3. Unity で **Assets → Import Package → Custom Package…** を選び、ダウンロードした `.unitypackage` を選択して内容をインポートします。
4. コンパイル後、**Tools → prokjs → VRChat World Optimizer** を開きます。

### 方法 2: Unity Package Manager（Git）

Unity で **Window → Package Manager → + → Add package from git URL…** を開き、次の URL を入力します。

```text
https://github.com/prokjs/texture-optimizer.git#v1.1.0
```

`com.prokjs.texture-optimizer` を v1.1.0 に固定してインストールします。Unity の Git インストールには Git が必要です。

### 方法 3: VRChat Creator Companion（VCC）

1. VCC の **Settings → Packages → Add Repository** を開きます。
2. 次のリスト URL を追加します。

   ```text
   https://prokjs.github.io/texture-optimizer/index.json
   ```

3. リポジトリを有効にし、**Manage Project** で **prokjs's VRChat World Optimizer** (`com.prokjs.texture-optimizer`) の **1.1.0** を追加します。
4. **Tools → prokjs → VRChat World Optimizer** を開きます。

VCC は任意のインストール手段であり、実行時の依存関係ではありません。

## 最初のバッチを安全に適用する

1. テクスチャの `.meta` ファイルを含め、**プロジェクトをコミットまたはバックアップ**します。
2. **Scope**、**Edit cap for** の対象、非アクティブなオブジェクトを含めるかどうかを選びます。**Scan / Refresh** をクリックします。
3. 表を確認します。編集可能な行に個別にチェックを入れるか、絞り込み後に **Select visible editable** を使用します。チェックはアセットの選択を意味し、インポーターの変更ではありません。
4. 行ごとに小さい **Proposed cap** を選ぶか、一括設定用のサイズを選んで **Propose for checked** をクリックします。提案は適用するまで読み取り専用です。
5. **Preview Apply checked...** をクリックします。すべての対象アセット名、上限の変更、プラットフォームオーバーライドの注意、バックアップ先を確認します。
6. 内容が正しければ **Apply these named resolution caps** をクリックします。結果とプロジェクト内でのテクスチャ品質を確認し、残したい変更だけをコミットします。
7. 最新の optimizer バッチを元に戻すには、**Restore Last Batch...** でプレビューを確認し、**Restore safe matching entries** をクリックします。後から加えた編集と競合する項目は上書きされません。

スキャンの対象範囲、推定値の読み方、バックアップの扱い、トラブルシューティングについては、[詳しいユーザーガイド](Documentation~/user-guide.ja.md)を参照してください。

## LOD とシーンの準備

**LOD & Analysis** の推奨事項は静的解析であり、プロファイラーの実測値や FPS 予測ではありません。既存の LOD レベルは Inspector で確認します。自動 LOD は適格な固定・不透明メッシュを選び、明示的なプレビューを確認してから適用します。LOD0 を保持し、縮小メッシュを新規アセットのキャッシュに保存します。削減率は**除去する頂点の割合**であり、三角形の割合や正確な結果を保証しません。トポロジー保持のため目標に達しない場合があります。各レベルと切り替えを目視確認してください。

元メッシュ、UV、マテリアル、コライダーは書き換えません。ピックアップ、Udon 制御対象、スキンメッシュ、マテリアルオーバーライド、ベイク済みライトマップの置き換えは推奨自動処理から除外します。保守的な適格判定も見た目の適切さを保証しません。

**Occlusion & Shadows** はプレビュー後に適切な対象の静的フラグを準備します。フラグだけでは実行時カリングにならず、別途 Unity のオクルージョンベイクが必要です。床の準備には適切な既存 UV2/GI が必要で、UV2 生成やライト変換はしません。照明ベイクは別の明示的な確認を伴う**シーン全体**の処理で、長時間かかる場合があります。必要ならキャンセルしてください。フラグ復元はベイク済み照明データを復元しません。既存のランタイムタープコントローラーも変更しません。

シーン変更には Undo または該当バッチの復元を使用します。復元後も生成 LOD `.asset` は Undo と保存済み参照の保護のため残します。復元はアセット削除ではありません。適用／ベイク前にシーンと照明データを保存・バックアップしてください。

## 重要な制限と安全上の注意

> **共有アセットへの変更です。** 上限の変更は、スキャンしたオブジェクトだけでなく、そのテクスチャを使うすべてのシーン、マテリアル、プレハブ、そのほかの参照元に影響します。

- **インポート元画像のピクセルは維持します。** インポーター上限／選択プラットフォームのオーバーライド変更後に再インポートします。ただし対応する独立 RGBA32/DXT1/DXT5 **ネイティブ Texture2D `.asset` は Default でピクセル自体を再サンプリング**し、全プラットフォームで共有します。事前に元バイトを保存し、GUID／ローカル ID、形式、ミップマップの有無、サンプラー設定を維持してミップマップを再生成します。使用前に[ガイドの適格／復元条件](Documentation~/user-guide.ja.md)を確認してください。
- **FPS 向上は保証しません。** 解像度を下げるとディテールと引き換えにインポート後の割り当て量を減らせる場合がありますが、フレームレートの向上や、あらゆるパフォーマンス上の問題の解消を保証するものではありません。
- **推定値は常駐メモリの実測値ではありません。** 現在の割り当て量の推定には、Editor に読み込まれたテクスチャのサイズとグラフィックス形式を使用します。選択対象と提案後の数値にも同じ形式を代用します。ストリーミング、プラットフォームの形式、実機でのフォールバック、アトラスへのパッキング、インポーターの丸め処理によって結果は異なります。**Android の推定値は代用形式による目安であり、Android 実機での測定値ではありません。**
- **一部のアセットは意図的にロックされます。** スプライト／アトラスの入力、生成されたライティング／反射アセット、パッケージ内・組み込み・一時的・埋め込みのテクスチャ、未対応の非 2D テクスチャ、安全にインポーターを編集できないアセットなどです。ロックされた行は情報表示用です。管理元のワークフローを回避して編集するためのものではありません。
- **シーン／選択範囲のスキャンは、完全な依存関係監査ではありません。** 対応するコンポーネント／マテリアルの参照を調べます。特に、アバターのアニメーションクリップだけから参照されるテクスチャやマテリアルの検出には**対応しておらず、検出できるとも主張していません**。フォルダー／プロジェクトのスキャンはテクスチャアセットの一覧であり、使用の有無を証明するものではありません。
- **テクスチャインポーター変更の Unity Undo は保証されません。** テクスチャバックアップとバージョン管理を利用してください。LOD／静的フラグには別の Undo／バッチ復元があります。
- **テクスチャバックアップはプロジェクト別ローカルデータ** `UserSettings/ProkjsTextureOptimizerBackups/` です。インポート画像は復元設定のみ、対応するネイティブアセットは元 `.asset` バイトも保存するためすべて保持してください。ネイティブ復元にはパス／GUID／メタデータ／適用後内容ハッシュの一致が必要で、移動／置き換え／後の編集は拒否します。テクスチャタブは最新バッチのみ扱います。
- **アンインストールしても上限は元に戻りません。** ツールを削除する前に、必要なインポーター変更を復元または差し戻してください。パッケージファイルを削除しても、ローカルのバックアップ記録は自動削除されません。
